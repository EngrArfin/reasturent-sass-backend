1 Executive Summary & Business Challenge

Modern food and beverage businesses operate in high-tempo, multi-station environments where milliseconds matter. Traditional single-station POS systems suffer from operational bottlenecks: waiter handwriting delays, kitchen communication chaos, inventory shrinkage, lack of real-time table turnover metrics, and fragmented payment reconciliation (combining cash, cards, and mobile financial services).

The Solution: This backend platform implements a high-throughput, cloud-native Multi-Tenant SaaS designed to empower independent restaurant owners (Supervisors/Managers) as well as global SaaS franchisors (Super Admins). With strict tenant data isolation, real-time KDS pipeline synchronization, visual table floor maps, instant SKU/barcode stock engines, and four-digit quick PIN authentication for high-speed counter handovers, the system achieves frictionless restaurant orchestration.

❌ Traditional Restaurant Bottlenecks Before SaaS
  • Order Latency: Waiters write paper slips, physically deliver them to kitchen, causing 10-15 min prep delay.
  • Billing Discrepancies: Manual discounts, voucher calculations, and untracked split payments lead to cash shortages.
  • Stock Blindspots: No real-time stock deduction on dish sales; frequent unexpected 86'd items during rush hour.
  • Multi-Tenancy Vulnerabilities: Complex setups risk accidental data sharing between franchise branches.
✅ SaaS Architecture Transformation After Solution
  • Instant KDS Stream: Floor orders dispatch in sub-100ms directly to kitchen display screens with modifiers.
  • Omnichannel POS Hub: Split settlement via Cash, Cards, and MFS (bKash, Nagad, Rocket, Upay) with automated voucher engine.
  • Automated SKU Engine: Integrated barcode/QR scanner, real-time inventory decrement, and low-stock alerts.
  • Strict Tenant Scoping: Scoped database queries keyed by businessId guarantee 100% data partition.
2 System Architecture & Multi-Tenancy Design

The backend is structured using NestJS modular architecture with Prisma ORM connecting to PostgreSQL. Multi-tenancy is enforced at the service layer: every restaurant tenant is encapsulated inside a unique Business model. All entities—including users, menu items, orders, tables, inventory products, vouchers, and support tickets—are bound by mandatory businessId relations.

4 Core Functional Modules & API Architecture

The backend is split into 14 decoupled feature modules. Each endpoint enforces strict data contracts, validation pipes, and Swagger OpenAPI schemas.

6 Security, Performance & Resilience Engineering
🔐 Enterprise Tenant Scoping: Every repository call executes an internal tenant validator (getEffectiveBusinessId). This guarantees that even if a malicious user crafts an ID belonging to a competitor restaurant, the Prisma ORM automatically blocks cross-tenant access.
🛡️ Defense-in-Depth Security
  • Bcrypt Encryption: Both user passwords and 4-digit quick POS access PINs are encrypted using salted bcrypt hashing.
  • Guard Layering: Global JwtAuthGuard paired with custom RolesGuard on sensitive mutation controllers.
  • Data Validation: Automated DTO validation via class-validator ensures sanitization before reaching business logic.
⚡ High-Concurrency Performance
  • Sub-Millisecond Queries: Strategic indexing on (businessId, status, barcode) ensures rapid lookups.
  • Connection Pooling: Managed PostgreSQL connection pool prevents memory exhaustion under heavy rush-hour orders.
  • Asynchronous Ticket Streaming: KDS ticket bumping operates without blocking client checkout requests.
